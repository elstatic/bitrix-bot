# setup-env (Codex)

## Codex адаптация
- Вместо `AskUserQuestion` используй `functions.request_user_input`.
- Не используй `Task(...)`/субагентов — их алгоритмы встроены ниже (если упомянуты).
- Команды из оригинала выполняй напрямую в этой сессии.

## Оригинальная инструкция

# Setup Environment Skill

Skill для настройки переменных окружения проекта.

## Когда активируется

Пользователь хочет задать вебхук, настроить окружение, подключить Битрикс24 или указать свои данные для API.

## Что делать

### 0. Помочь получить вебхук (если у пользователя его нет)

Если пользователь не знает, где взять вебхук, **обязательно** сначала дай простую инструкцию ниже, и только потом запрашивай URL.

Коротко подскажи, где взять вебхук в Битрикс24:

1. **Приложения → Разработчикам → Другое → Входящий вебхук**
   - Прямая ссылка: `https://ваш-домен.bitrix24.ru/devops/section/standard/`
2. Выбери права (scopes):
   - `task` — задачи
   - `im` — чаты
   - `calendar` — встречи
   - `user` — профиль
3. Сохрани и скопируй URL вида:
   `https://ваш-домен.bitrix24.ru/rest/USER_ID/WEBHOOK_CODE/`

### 1. Спросить вебхук

Если пользователь не указал вебхук в сообщении, спроси через `AskUserQuestion`:

> Укажите ваш Bitrix24 Webhook URL (формат: `https://ваш-домен.bitrix24.ru/rest/USER_ID/WEBHOOK_CODE/`)

### 2. Спросить папки с проектами (опционально)

Спроси через `AskUserQuestion`:

> В каких папках лежат ваши git-проекты? (если нет — можно не настраивать)

Варианты:
- **Нет папок проектов** — пропустить настройку `PROJECTS_DIRS`
- **Указать свои** — пользователь введёт список папок

Если пользователь выбрал «Указать свои», попроси ввести пути (через запятую, пробел или по одному). Сконвертируй в формат с разделителем `:` для переменной `PROJECTS_DIRS`.

Примеры:
- Ввод: `~/Projects, ~/work/clients` → `PROJECTS_DIRS="~/Projects:~/work/clients"`
- Ввод: `~/Projects` → `PROJECTS_DIRS="~/Projects"`
- Если выбрано «Нет папок проектов» → `PROJECTS_DIRS` **не задавать**

### 3. Создать или обновить `.env`

Файл `.env` находится в корне проекта. Формат:

```
export BITRIX24_WEBHOOK_URL="https://ваш-домен.bitrix24.ru/rest/USER_ID/WEBHOOK_CODE/"
export PROJECTS_DIRS="~/Projects"  # опционально
```

- Если `.env` уже существует — обнови только строку `BITRIX24_WEBHOOK_URL` и, если пользователь указал папки, строку `PROJECTS_DIRS`. Остальные переменные не трогай.
- Если `.env` не существует — создай его.

### 4. Добавить `.env` в `.gitignore`

Проверь, что `.env` указан в `.gitignore`. Если нет — добавь строку `.env` в конец файла. Если `.gitignore` не существует — создай его с содержимым:

```
.env
```

### 5. Проверить подключение

После сохранения вебхука выполни тестовый запрос:

```bash
source .env && curl -s "${BITRIX24_WEBHOOK_URL}profile.json"
```

Если `curl` в этой среде не резолвит домен, fallback:
```bash
python3 .claude/scripts/bitrix_call.py profile
```

Если запрос вернул данные пользователя — сообщи об успехе и покажи имя подключённого аккаунта.

Если ошибка — сообщи пользователю и предложи проверить URL.

### 6. Разрешения на команды (для Codex)

Объясни простыми словами, что Codex может периодически запрашивать разрешение на «обычные» команды, и предложи заранее подтвердить безопасный набор. Спроси через `AskUserQuestion`:

> Разрешить выполнять обычные команды без лишних вопросов?  
> (git, python, bash/zsh, ls/cat/sed/grep/rg, mkdir/cp/mv)

Если пользователь согласен — сообщи, что при первом появлении запроса надо нажать «Allow», и дальше Codex запомнит разрешение.

### 6. Подтверждение

После успешной настройки выведи:

```
Окружение настроено:
- .env создан (вебхук сохранён)
- Папки с проектами: [значение PROJECTS_DIRS] / «не настроены (сканирование проектов пропущено)»
- .gitignore обновлён (.env не попадёт в git)
- Подключение проверено: [имя пользователя]
```
