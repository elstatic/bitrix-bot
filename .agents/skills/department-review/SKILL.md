# department-review (Codex)

## Codex адаптация
- Для уточнений и подтверждений используй `functions.request_user_input` (или обычный вопрос в чате, если инструмент недоступен).
- Не используй `Task(...)`/субагентов.
- Команды выполняй напрямую в этой сессии.

## Назначение

Скилл формирует управленческий отчёт по сотрудникам отдела за период:
- задачи: создано / закрыто / просрочено;
- встречи;
- коммуникации в Битрикс24:
  - личные диалоги `я ↔ сотрудник`,
  - общие групповые чаты (по сообщениям сотрудника в чатах, доступных владельцу вебхука).

## Источник данных

- Bitrix24 webhook из `.env`: `BITRIX24_WEBHOOK_URL`
- Скрипт: `.claude/scripts/department_review/main.py`

Если `.env` отсутствует или вебхук не задан — предложи использовать скилл `setup-env`.

## Правила запуска

1. Всегда определить период.
- Если период не указан пользователем, обязательно уточни `с` и `по`.

2. Всегда определить отдел.
- Предпочтительно: по названию (`--department "<название>"`).
- Если пользователь дал ID — можно `--department-id <ID>`.

3. Запускать скрипт:

```bash
python3 .claude/scripts/department_review/main.py \
  --from 2026-02-01 \
  --to 2026-02-15 \
  --department "Отдел разработки"
```

4. Если нужно машинно обработать ответ — запускай с JSON:

```bash
python3 .claude/scripts/department_review/main.py \
  --from 2026-02-01 \
  --to 2026-02-15 \
  --department "Отдел разработки" \
  --format json
```

## Обработка неоднозначного отдела

Если скрипт вернул `needs_selection=true` и список `department_candidates`:
1. Покажи пользователю варианты.
2. Попроси выбрать ID.
3. Перезапусти с `--department-id <ID>`.

## Опциональные параметры

- `--include 12,34` — вручную добавить сотрудников по ID.
- `--exclude 56,78` — исключить сотрудников по ID.
- `--chat-limit 300` — лимит диалогов.
- `--max-chat-pages 5` — лимит страниц сообщений на диалог.

## Формат ответа пользователю

По умолчанию возвращай Markdown-отчёт скрипта как есть.

Если пользователь просит коротко:
- сначала блок «Итого по отделу»,
- затем 3-5 главных рисков (просрочки/нулевая активность),
- затем инструкция как получить полный отчёт (запуск без сокращения).
